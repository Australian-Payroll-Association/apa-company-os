Vercel vs AWS

Platform and cost comparison for the current stack — Next.js apps deployed via git push → CI/CD, with Claude Code operating the tooling. Prepared August 2026.

How Claude Code hooks into each

Vercel (current)AWS
Primary interface Vercel MCP (OAuth'd, read-only per house rules) + Vercel CLI AWS CLI via Bash — covers ~300 services; broader than any MCP
MCP servers Official Vercel MCP, already connected AWS Labs suite: aws-api, CloudWatch, CDK, Terraform, cost analysis, docs lookup
Deploy trigger git push → Vercel builds & ships automatically git push → GitHub Actions → SST/CDK deploy (you assemble the pipeline once)
Auth model One-time OAuth, done IAM — best via aws configure sso (short-lived tokens, no keys on disk)
Read-only guardrail Enforced by house rule (Vercel CLI/MCP read-only) Enforced by IAM policy — give the local profile ReadOnlyAccess; writes go through CI only
Logs & debugging Build logs, runtime logs, analytics via MCP CloudWatch Logs/Insights, X-Ray tracing — deeper but more assembly required
Setup effort Zero — already running ~1 day one-time: SST or CDK in repo, OIDC role for CI, SSO profile locally

Platform trade-offs

VercelAWS
Philosophy Opinionated — platform figures out builds, CDN, SSL, previews Unopinionated — total control, you assemble every layer
Next.js fit First-party (Vercel makes Next.js) — zero-config ISR, image optimization, edge Good via SST / OpenNext — near-parity, occasionally lags new Next.js features
Preview deploys Automatic per-PR, free with the plan Possible (SST supports it) but you build and pay for each environment
Beyond web apps Limited — functions max ~5 min, no queues, no private networking Unlimited — long-running jobs, SQS queues, VPCs, RDS, batch, ML, anything
Ops burden Near zero Real — IAM hygiene, cost monitoring, dependency on your own IaC quality
Lock-in Moderate — Next.js is portable, but platform features (analytics, edge config) are not Low-to-moderate — IaC is portable-ish; services like DynamoDB are sticky
Cost predictability High — flat seat price until you cross usage tiers Lower — pure usage-based; cheap at low traffic, needs monitoring at scale

Cost comparison

Estimates for a typical marketing/content Next.js site (like this one) at three traffic levels. AWS figures assume SST/OpenNext on Lambda + CloudFront + S3, us-east-1. All USD/month.

Vercel

Low traffic ~50k visits/mo

$0–20 /mo
  • Hobby tier: free (non-commercial only)
  • Pro: $20/seat, includes 1 TB fast data transfer + generous function quota
  • Usage almost never exceeds included allowance at this level
AWS

Low traffic ~50k visits/mo

$1–10 /mo
  • Lambda: mostly inside free tier (1M req + 400k GB-s free)
  • CloudFront: ~$0.085/GB after 1 TB free tier
  • S3 + Route 53: ~$1–2
Vercel

Medium traffic ~500k visits/mo

$20–60 /mo
  • Pro seat(s) + occasional usage overage
  • Fast data transfer beyond 1 TB: ~$0.15/GB
  • Image optimization & edge requests can add $10–30 if media-heavy
AWS

Medium traffic ~500k visits/mo

$15–40 /mo
  • Lambda + API Gateway/Function URLs: $5–15
  • CloudFront transfer: $10–20
  • Assumes good caching; poor cache config can double this
Vercel

High traffic ~5M visits/mo

$250–800+ /mo
  • Usage-based charges dominate the seat price
  • Bandwidth is the big line item at ~$0.15/GB
  • Enterprise plan often triggered around this scale
AWS

High traffic ~5M visits/mo

$100–350 /mo
  • CloudFront ~$0.085/GB — roughly half Vercel's bandwidth rate
  • Lambda scales linearly; consider provisioned concurrency for hot paths
  • This is where AWS clearly wins on raw dollars
The hidden cost line AWS's dollar advantage at scale buys real operational work: IAM upkeep, cost alarms, cache tuning, and owning your own deploy pipeline. At current traffic levels, the money saved is small enough that Vercel's zero-ops model is effectively cheaper once your time is priced in — in Human Tokens terms, an hour of skilled attention spent on infrastructure is worth more than the $10–30/mo delta.

Verdict for this stack

Stay on Vercel for the Next.js web properties while traffic and needs stay in the low-to-medium band. The workflow (git push → CI/CD, read-only MCP for status) is already exactly right, and Claude Code operates it fully today.

Add AWS selectively when a need appears that Vercel can't serve: long-running jobs, queues/workers, private networking, or heavy data workloads. A hybrid — Vercel for the front-ends, AWS for backend services — is a common and clean split, and Claude Code can drive both sides from the same session.

Revisit a full migration only if monthly Vercel spend passes roughly $300–500, at which point SST-on-AWS pays back the one-day setup within a couple of months.

Prices reflect published Vercel Pro and AWS on-demand rates as of early 2026 and are estimates — verify against current pricing pages and your actual usage before committing. Prepared for the ai-officer-web / Edge8 stack.
