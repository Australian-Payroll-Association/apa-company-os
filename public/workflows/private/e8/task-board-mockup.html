Mockup notes (not part of the UI):
  • Columns are per-board data, not a fixed enum. Every board seeds with To do / Doing / Waiting / Done and can rename or reorder its own.
  • COMMITMENT badge = card linked to a coaching commitment via subject_type/subject_id. Marking the card done marks the commitment kept, one-way.
  • AGENT badge = card filed by a scheduled routine (fleet fitness, QBO sync). Agents are ordinary board users.
  • Amber clock uses task_stage_log, same pattern as application days-in-stage.
  • Done cards archive after 14 days (timestamp flag, never deleted: the app role has no DELETE grant).
  • "My tasks" filter also exists as a cross-board list on /team.
  • A board optionally links to a client. On client boards, cards can link to items on that client's roadmap (ROADMAP badge, picker scoped to that client). Same subject_type/subject_id slot as commitments; a card is about one thing.
  • Seed boards: AIOlabz, Operations, 8 Edges, Australian Payroll (client), Work Healthy (client), Arca Wellness (client), EO Global.
  • Visibility: admin sees every board; team members see only boards they are members of (auto-added when assigned a card); clients see their linked board in the portal, minus cards marked internal.
  • Sprints are per-board and optional: a sprints table (name, start/end, goal) and a nullable sprint on the card. The toolbar picker defaults to the active sprint; "no sprint" = backlog or ongoing ops work. Sprint is time, columns are state: never a sprint column.
