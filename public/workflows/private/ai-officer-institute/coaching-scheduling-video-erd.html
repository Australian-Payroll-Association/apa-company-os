Locked decisions (rounds 1–3, 2026-08-07)

micro_session is DELETED, not migrated. A micro-session IS a course row — type='micro_session'. Both carry a pass score; the old table's scheduling/host columns move to live_event, and its content was stale pilot data (we're re-authoring). micro_session_completion dies with it — completion rides normal course progress.
Graduation = college model. course.requirement = core | elective; certification.electives_required. Complete = all core courses + at least N electives. Micro-sessions count — as electives.
Elective credit is spent once, globally. An elective applies to whatever certification the student is pursuing when they pass — even cross-track (a Leadership elective can count toward AI Officer). Applied to Agentic ⇒ never reusable for Leadership. elective_credit persists the allocation: UNIQUE(user_id, course_id), with certification_id recording where it was spent. The course's own certification_id is just its home-track label.
Credit comes from the graded challenge, never watch time (locked by the prototype). Micro-session credit = submission → assessment ≥ pass mark. Watch minutes are logged for the coach and program manager only.
Coaching earns no credit — confirmed by the prototype: coaching is community; micro-sessions are the electives.
Topic voting is first-class — "the top-voted topics get coached." topic_vote: one row per (topic, member), UNIQUE pair. Vote counts are aggregates, never a column.
Coaching sessions are categorized + tagged like videos — the archive filters by track and searches tags. category_link gains live_event_id; live_event gets tags text[].
One generic live_event table, one pointer. event_type = coaching | class; single nullable course_id. Coaching has no course (FK NULL); a class of any type points at its course. CHECK event_surface_shape ties type↔FK. Re-runs: one course, many events.
Homework needs zero schema surgery. A micro-session's assignment is an activity row under its course — submission, assessment, scorer, grade card all untouched. The old plan's nullable-FK + resolver branch is dead.
One video_placement table — a nullable real FK per surface + CHECK exactly-one-set. "Where does this video appear" and "all videos on this course" are single queries; Postgres still enforces every reference. New surface = add a column, not a table. (Supersedes the per-surface video_on_* doctrine.)
category has a type — certification | collection, extensible — so surfaces can display the right slice (the 3 certifications are the main categories; more taxonomies can join later). One category_link join table, same exactly-one-of idiom. tags text[] stays a free folksonomy on video.
Signup is one row with a lifecycle — signed_up_at / attended_at / cancelled_at; partial UNIQUE on live rows. Walk-ins get an attended-only row. Archive attendee list = attended_at IS NOT NULL.
Topics are body-only, visible to the group, with a NULLABLE event FK — "move to next week" = re-point the FK. Max 8 accepted per event is an app rule, never a constraint.
key_learnings + resources live on live_event — coaching, micro-session classes, and cert classes inherit them for free. Both are jsonb lists: learnings render as discrete takeaways, resources as [{title,url,kind}].
Polished-replaces-Zoom = video.superseded_by_video_id. Display rule everywhere: hide superseded. Nothing is deleted — the transcript source survives.
Watch tracking = one upsert row per (user, video). Fed by FE IFrame-Player heartbeats — our own build; YouTube's APIs cannot attribute minutes to a logged-in learner. Completion threshold is an app rule.
One track at a time = soft pointer app_user.current_certification_id — switchable, no entitlement state machine.
Coaching recordings are video rows via a video_placement on the event — never a bare URL (the recording_url pattern #1100 is retiring). They stay status='draft' → library-hidden unless deliberately published.
House conventions: uuidv7 PKs, text + CHECK (never native enums — the material_type lesson), trg_touch timestamps, RLS enabled with no policies (service-role only, like video).

Assumptions pending Dave

electives_required per certification — the number itself is unset (prototype shows 10). Also: can a standard course be an elective, or only micro-sessions? Schema allows either.
Archive session numbering (#012) — computed ordinal over completed coaching events, or a stored column. Assumed computed; no schema either way.
"Replace" resolved as display-rule (keep both videos, hide superseded) — Khoa's call; confirm in passing since deletion would destroy the transcript that key-learnings generation needs.

Impacted code seams

Grading pipeline: zero change. Micro-session homework is an activity — submission_resolver.py keeps its single path. (The previous draft's resolver branch is cancelled.)
Progress computation grows the elective rule — cert complete = all-core-complete + count(elective_credit WHERE certification_id = this cert) ≥ electives_required. Passing an elective's challenge writes the elective_credit row against app_user.current_certification_id — insert-or-nothing (spent-once).
micro_session endpoints + FE pages repoint to course filtered on type='micro_session'; the table, its completion table, and video_on_micro_session writers are deleted, not migrated (nothing live to customers).
Library query grows three reads: category_link join, hide-superseded filter, per-user watch stats.
New FE↔BE seam: player wrapper posts progress heartbeats → video_watch upsert endpoint. This is what makes "watched the recording ⇒ credit" enforceable.
"All live sessions we run" — Dave's analytics ask — stays one query over live_event, no UNION.
