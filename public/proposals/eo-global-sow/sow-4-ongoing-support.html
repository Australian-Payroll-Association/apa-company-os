01

Scope of the engagement

Chapter rollout

  • Onboard chapters onto the event integration — take each chapter's access and configure the connection for them.
  • Coordinate and support go-live — walk each chapter through it and confirm events land correctly.
  • Monitor connections — watch the state of every connection through the shared tracker.

Bug fixes & minor improvements

  • Bug fixes — fix breakages when Eventbrite, Hivebrite or HubSpot change something.
  • Minor feature improvements — small enhancements the team picks up within its capacity, prioritised with you.
⛊Larger new features are scoped as their own SOW. This team handles the continuous, small-and-steady work.

Customer-feedback tracker

Build the owned feedback loop so insight comes from the customer, not internal guesswork — and so it can be measured and acted on continuously.

  • Interview format & playbook — a standard structure anyone on the team can run.
  • Cadence & surveys — a tracked number of interviews per week, plus lightweight surveys, into one intake.
  • Single intake + usage data — feedback captured where chapters already log interest, enriched with product usage.
  • Quantify & qualify — turn raw feedback into measurable signal on a regular readout.
  • One place — lives in the shared rollout tracker from SOW 2, so rollout and feedback sit side by side.

Assumptions & dependencies

Assumptions

  • Builds on the event integration delivered in SOW 2, after the go / no-go.
  • Chapters provide Eventbrite access; the team configures it for them.
  • Runs against the shared rollout tracker; the feedback tool lives there too.

Dependencies / open

  • Team size, allocation and monthly rate to be agreed.
  • Rollout order and pace for the ~60 chapters.
  • How minor-improvement priorities are set each cycle.
  • Where the feedback intake lives, confirmed with the sponsor.
